A Job Through the Machine

A job document is a program. The engine compiles it into a factor graph, a state and a deal tree, then executes it batch by batch against simulated paths. Press play.

    What the design buys

    The engine is a virtual machine: the job is the program, the compile is table-driven, and the execute loop is the same four verbs for every model. Each property below is what one of the chapters shows.

    One Factor keys everything

    A factor is a (type, name) pair, the one identity across the discovery graph, the offset maps, the object graph, the tenor payloads and the runtime buffers. Layers compose without a translation table.

    The compile is idempotent

    Discovery and the model split read the configuration and write nothing, so a validate, a want-list and a run see the same universe, and no placeholder ever pollutes saved market data.

    Registries, not functions

    Which factors exist is three plain dictionaries: the edges a factor type embeds, the name-prefix chain, and the instrument-conditional lambdas. A new factor type is a row, never an edit to a dispatcher.

    Canonical order

    The sort visits factors by type and name, so the rows each process draws from are a function of the graph alone, never of the order deals were booked. That is what makes a refactor provable bit for bit.

    Publish as you go

    Each process writes its path to the scenario buffer as it generates, under its own key, so a linked factor reads its parent's finished path and the loop never names a model.

    Two memos, two lifetimes

    t_Buffer is cleared every batch and by every fork; t_PreCalc holds what every batch reads unchanged and is uploaded once per calculation.

    The inner block is canonical

    Every inner simulation reads one scrambled Sobol block, a function of its shape alone, so a trade's value does not depend on what is booked before it and a book shards with nothing to anchor.

    The position is the storage

    The recompute node saves where the generator stood, never what it drew, and re-runs the same simulation in backward one block at a time, trading the tape for a second forward pass.

    A correction worth zero forward

    A decision on simulated state registers its gap with its graph; the boundary correction adds the flux the indicator loses and changes nothing reported.

    The reconciled core

    The batch loop's reductions and the base valuation's execute are what everything downstream reconciles against; they are not touched, and the one wiring into them is the correction above.

    The example job is a netting set of three deals on a USD book: a swap, an FX option and an index autocall, the autocall under a fitted spot model. Counts and names are illustrative.
