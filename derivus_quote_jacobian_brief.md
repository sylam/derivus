# Derivus workstream brief: market-quote sensitivities via calibration Jacobians

Target repository: `github.com/sylam/derivus` @ `main` (as inspected 2026-08-08). This brief assumes you have the repo checked out and have read `docs_src/developer/architecture.md`, `dependency_system.md`, `conventions.md`, `calc_lifecycle.md`, and `roadmap.md` before writing any code. House rules apply throughout: registries not functions; look-before-you-write (search `utils.py` and the resolver layer for an existing equivalent before adding anything); forward values must remain bit-identical when new machinery is toggled on; tests follow the calibrated-parameter fixture pattern (no licensed market data); the PolyForm Noncommercial licence header stays intact; prefer solvers already vendored in the codebase before adding dependencies.

## Objective

Today the autograd tape begins at calibrated factors: curves, vols, and model parameters arrive as data, so `Greeks` are reported in calibrated-factor space (zero-curve nodes, HW2F parameters). Desks explain P&L in quote space (par swap rates, FRA/futures strips, OIS quotes, swaption vols). This workstream extends the tape one layer upstream so that a single backward pass yields dV/dq for market quotes q, by owning the bootstrap inside the library and differentiating through its fixed point. It subsumes three roadmap items — curve bootstrapping from FRAs and swaps, better RFR/OIS handling, and "sensitivities to market quotes by carrying the calibration Jacobian through bootstrapping" — and they must be built in that order.

## Architecture

The chain is: quote tensors q (float64 leaves, `requires_grad=True`) → bootstrap solve producing calibrated node values θ* → the existing factor buffers consumed by scenario generation and pricing → portfolio objective V → one `backward()` yields dV/dθ and dV/dq together, with the boundary corrections composing unchanged.

Differentiation through the solve uses the implicit function theorem at the calibration fixed point, never an unrolled solver. Wrap the bootstrap in a custom `torch.autograd.Function` (this pattern already exists in the codebase — mirror its style). Forward runs the ordinary damped-Newton solve to convergence in float64 and returns θ* exactly as the plain solver would — same iterations, same tolerances — so enabling gradients cannot move a mark. Backward receives the cotangent v = ∂L/∂θ*, solves the transpose linear system (∂F/∂θ)ᵀ w = v, then returns ∂L/∂q = −(∂F/∂q)ᵀ w, where the second contraction is a vector-Jacobian product of the residual function in q at fixed θ*. Both ∂F/∂θ (an n×n matrix, n = number of benchmark instruments, small) and the q-side VJP come from autograd applied to the residual closure itself, so the residual code is written once and differentiated twice. Cast θ* to the cube dtype at the Function boundary; the bootstrap and its Jacobian stay in float64 regardless of simulation precision, and this precision seam must be documented.

The residual system is priced by the library's own deal pricers. Benchmark instruments are defined as ordinary deals in JSON (deposits/FRAs, OIS swaps, par IRS built from the existing leg vocabulary via `Children` composition), with the quote entering as the fixed rate or price such that a fair instrument has zero PV: F_i(θ, q) = PV_i(θ, q_i) evaluated at t0. This dogfoods the same-pricer-everywhere principle and means quote definitions are data, consistent with the conventions-as-data posture (the six-basis daycount enum and `calendars.cal` are the only convention kernel; do not grow it beyond what the benchmark set needs). You will need a cheap t0-only valuation closure over a small deal set; audit whatever baseval path exists for `.detach()` calls, numpy round-trips, or buffer copies that would sever the graph between θ* and the factor objects — the known "factor silently becomes static" behavior suggests detach points exist on the factor-construction path, and finding and gating them is part of this increment, not incidental to it.

## Increment 1 — multi-curve linear rates

Scope: single currency, OIS discount curve bootstrapped from OIS quotes plus one projection curve from FRAs/futures and par swaps, with compounded-in-arrears RFR conventions handled correctly first — this is the spine of every realistic netting set and takes priority over elegance elsewhere. Deliverable: bucketed par-quote deltas for a linear-rates book, produced in the same backward pass as existing factor greeks. Build order within the increment: the t0 benchmark-valuation closure and its graph audit; the plain multi-curve solver; the IFT wrapper; factor-buffer attachment; gates.

## Increment 2 — model-parameter calibration

Wrap the existing HW2F swaption-vol calibration (see `DV_Bootstrap`) in the same IFT contract. The fixed point is the stationarity of the least-squares loss, so backward uses the Gauss–Newton approximation of the Hessian; document the inexact-fit caveat (the dropped residual-curvature term) and its tolerance. This routes swaption-vol vega into quote space. FX vol follows the same shape. Do not attempt vol-surface parameterisations (SABR/SSVI) here.

## Validation and gates

Fixtures are round-trip and synthetic: construct a known θ_true, generate quotes by pricing the benchmark set off it, then require the bootstrap to recover θ_true to tight tolerance — self-contained and licence-clean. Verification is a triangle: the one-pass dV/dq must agree with dV/dθ contracted against a finite-difference dθ/dq, and both must agree with a full common-random-numbers quote-bump ladder reusing the existing ladder harness, scored on agreement and flatness separately. Additionally require the benchmark identity (the quote-delta of freshly bootstrapped benchmark i is δ_ij through the full chain, within tolerance), forward bit-identity (a reference exposure run is `np.array_equal` with quote gradients toggled on and off, mirroring the boundary-correction gate), and one mutation gate: a deliberate sign flip in the backward linear solve must fail the ladder — the gates must be able to notice this subsystem breaking, a known weakness of the boundary-term gates that this workstream should not repeat. Add a page under `docs_src/developer/` specifying the IFT contract, the precision seam, and the non-goals.

## Non-goals

No SIMM aggregation or regulatory formatting (bucketed quote deltas are the raw material; stop there). No wrong-way risk. No recalibration inside the simulation — quote sensitivities are t0 risk; future-dated dynamics remain on calibrated parameters. No new instruments and no changes to `instruments.py` pricers beyond what the t0 closure strictly requires.

## Acceptance criteria

The increment is complete when: round-trip fixtures recover θ_true to 1e-10 in float64; the validation triangle closes within Monte Carlo confidence and the quote-space ladder is flat in bump size; the benchmark self-delta identity holds to 1e-6; forward exposure output is bit-identical with quote gradients on and off; the sign-flip mutation fails the gate; and the developer docs page exists. Anything short of all six is not done.
